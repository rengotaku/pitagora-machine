# ADR 0005: レイアウト拡張は一様スケーリングではなく既存ランプ区間への追加ギミック方式を採る

## 背景

issue #10 は「装置が論理ワールド 1600x900 の対角線上に配置されており、右上・左下に空白が残っている」という課題に対し、3つの案を提示していた。

1. 右上の空白へ仕掛けを増やし、発射装置から坂2 への区間を経由させる
2. 左下の空白へエレベーターの経路を伸ばす、または待機床まわりに仕掛けを足す
3. 装置全体を少し拡大して四隅へ寄せる（各パーツの相対位置を保ったままスケールする）

issue 本文は「3番目が最も安全（相対関係が変わらない）」と評価していたが、実装前に座標を実測したところ、この評価は成り立たないことが判明した。

## 検討した代替案

### 案3: 一様スケーリング（不採用）

全パーツの座標からバウンディングボックスを算出したところ、X: 199〜1407 / Y: 35〜810（ワールド 1600x900）で、**縦方向はすでに上端余白 35px しかない**。中心からの一様拡大は、この上端制約により拡大率 1.08 倍（8%増）が限度で、視覚的に意味のある変化を生まない。

より根本的な問題として、右上・左下が空くのは対角線状の配置そのものが原因であり、**中心からの一様拡大は既存パーツが「今向いている方向」に伸びるだけで、「無い方向」（右上・左下）には伸びない**（既存のどのパーツも右上・左下方向を向いていないため）。

→ 座標の実測というただ 1 つの一次情報で、issue が「最も安全」と評価していた案が幾何学的に無効であると判明した。設計判断は必ず実測座標から行い、issue に書かれた評価を鵜呑みにしない。

### 案1+2: 新規仕掛けの追加（採用）

issue #3 で実証済みの安全パターン（新しい仕掛けは ramp1/ramp2 という長い直線区間の「上」に追加のボディとして載せる。既存のシュート同士の接続点には触れない）を踏襲する。

## 決定

- **左下（STEP1, PR #24）**: ramp2 の左寄り区間（x=560 付近、エレベーター受け渡し接続点 x=460,y=690 から 100px 以上離れた上流側）に `lowerPendulum` を追加
- **右上（STEP2, PR #25）**: ramp2 の右寄り区間（x=1180 付近、発射装置の着地点 1216,424 から離れた下流側）に `upperPendulum` を追加
- 両者とも既存の坂1振り子と同じ `armLength=78` を踏襲し、**振り子の最下点が最大径ボールの上端より確実に高い位置にとどまる**よう実測で確認してから配置を確定した
- `launcher` / `elevator` / `ramp1` / `ramp2` の座標・パラメータには一切触れない

### 3回の実測ベース再設計を要した理由（STEP1）

lowerPendulum は初回実装で `armLength=120`（既存の坂1振り子の78より大幅に長い）を採用し、ボールが坂面に接近しすぎて弾き返され、`wheel` との間で無限往復（ロックステップ増加）が発生、`gimmicks.elevator` の周回数が基準の約8分の1（9）に激減した。

2回目の修正で `armLength=78` に短縮したが、今度は坂面から離れすぎて全く干渉せず、無減速のボールがエレベーターへ突っ込んで跳ね、受け皿外へ脱落する新たな問題を誘発した。

3回目で「最下点がボール上端よりわずかに高い位置（マイルドタッチ）」に収束し、装置の中核ループを劣化させずに視覚的拡張を達成した。

## ヘッドレス環境の測定値ノイズについて

issue #10 記載の DoD 基準（`gimmicks.elevator` 64〜72）は別環境（おそらくヘッドフル）で計測された値だった。本 ADR の検証では、**ヘッドレス環境では MAIN（無変更）自体も同条件で elevator=8〜20 まで run ごとに大きくばらつく**ことを確認した（docs/verification.md の「ヘッドレス環境では急変イベント数が過大に算出される」という既知の注意点と同種の環境依存）。

このため、絶対値を issue 記載の基準とそのまま比較するのではなく、**同一ヘッドレス環境での MAIN との相対比較**（複数回の傾向で判定）を採用した。

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 新規振り子の周期・振幅・ボブ半径・センサー範囲。装置の見た目や検知感度に影響するが、既存の物理接続には影響しない
- **壊すと危ない**: 新規ギミックの `armLength` を既存の坂1振り子（78）より長くすること。坂面への接近度が変わり、ボールを弾き返すロックステップ往復を再発させる可能性が高い
- **壊すと危ない**: `launcher` の弾道パラメータ、`elevator` の座標・速度、`ramp1`/`ramp2` の座標・角度。過去に何度も破綻した最も壊れやすい箇所（ADR 0001, 0004 参照）
