# ADR 0004: 発射装置およびエレベーターの位置書き換えを撤廃しキネマティック駆動と引き込み整列動作を採用する

## 背景

物理シミュレーションの稼働中、1 フレームでボールが 36px（ボール直径）を超えて移動する瞬間移動（ワープ）や急激な速度跳びが多数発生していた。原因を1フレームずつ追跡した結果、以下の2パーツで位置・速度の一括変更が行われていたことが判明した。

1. **発射装置 (launcher)**:
   シュートから流れてきたボールが発射位置 `(1140, 440)` 付近に自然到達しない場合があり、タイムアウト判定によって最大 50px 離れた位置から空中の一点へ 1 フレームで一括スナップ（ワープ）されていた。
2. **エレベーター (elevator)**:
   - **キャリアの移動**: 静的ボディ（`isStatic: true`）の carrierBase を素の `setPosition` で毎ステップ動かしていたため、物理エンジン上でキャリアの速度 `velocity.y` が 0 のままであり、上昇中にめり込んだボールが衝突解決によって上へ激しく弾き飛ばされていた。
   - **払い出し**: `dispensing` 状態で `setVelocity(ball, { x: 8, y: -2 })` を 1 フレームで一括適用していたため、18px/frame の急激な速度跳びが発生していた。
   - **待機ボールの受け渡し**: 待機床（y ≈ 804）に留まるボールをキャリア内（y = bottomY + 10 = 770）へ一括で 44px ワープさせていた。

## 決定

連続性要件（1 フレームの変位 36px 超 0 件、急変イベント 30 件/分以下）と装置の安定稼働を両立するため、以下の設計を採用した。

### 1. エレベーター・キャリアのキネマティック駆動化

素の `Matter.Body.setPosition` を破棄し、`src/machine/kinematic.ts` の `setBodyPosition(body, position, true)` に置き換えた。
これによりキャリアに正しく上昇速度（`carrierBase.velocity.y < 0`）が保持され、物理エンジンが相対速度を計算できるようになってめり込み弾きが解消された。

### 2. 払い出し初速の段階的立ち上げ

`dispensing` 状態でのボール速度更新において、1 ステップで一括 8.0px/step を適用するのをやめ、毎ステップ `+2.0px/step` ずつ最大 8.0px/step まで段階的に増量するロジックに変更した。

### 3. 発射装置およびエレベーター待機床での「引き込み整列動作」の採用

位置書き換えを一括で実行せず、以下の仕様による**スムーズな段階的整列移動（Aligning Motion）**に統一した。

- **段階的移動**: 毎ステップ移動量を 1px → 2px → 3px → 4px と滑らかに引き上げ、1 フレームあたりの最大変位を 4px 以下に封じ込める。
- **整列中の一時的非衝突化**: 整列引き込み中のみボールの `collisionFilter.mask` を `0` に変更し、周囲のシュート等の静的ボディとの反発衝突を完全に無効化する。整列完了（または領域脱落・reset時）に元の `originalMask` へ確実に復元する。

#### なぜエレベーター待機床の受け渡しで物理傾斜シュート＋可動ゲートではなく整列動作を選択したか

当初検討された傾斜シュート＋可動ゲート方式では、34px の高低差においてボールがシュートからキャリア底板へ落下する際の反発やボウリング効果（受け皿内での跳ね返り）が発生し、100% 安定した受け渡しが困難であった。
STEP2 の発射装置で確立された「毎ステップ最大 4px の衝突無効化引き込み整列」を適用することで、物理的着地の乱れを完全に排除し、視覚的にも「パーツがボールを吸い寄せる」自然な動作としてワープ 0 件を確定的に担保できるため、本方式を採用した。

## 影響・効果

- 1 フレームあたりの変位が 36px（ボール直径）を超えるワープ現象が完全解消（0 件）。
- 急変イベントが大幅に抑制され、基準値（30.0 件/分以下）をクリア。
- 発射の瞬間の位置・速度は従来設定と完全に一致するため、既存の物理放物線軌道・ギミック巡回比率（1:1）に一切悪影響を与えない。
