# ADR 0006: 連鎖アニメーション（Kinetic Chain No.10）は物理エンジンを使わず、トップとは別ページに置く

## 背景

ピンボールとピタゴラ装置を組み合わせた連鎖アニメーションを別に作り、このリポジトリの Pages でも見られるようにすることになった（issue #29）。1 個の鋼球が 28 段の仕掛けを順に起動し、毎回同じ動きでゴールまで届くことが作品の前提になっている。

トップの装置は Matter.js で複数のボールを回し続けるもので、ボールごとに軌道が変わることを前提にしている（ADR 0001〜0005）。連鎖アニメーションはその逆で、「物理エンジンに任せた結果、毎回動きが変わって最後まで届かない」状態を避けるために作り方を選んでいる。

## 決定

- `public/chain/index.html` に HTML 1 ファイルとして置き、Pages の `/pitagora-machine/chain/` で配信する。トップの装置、テスト、ADR 0001〜0005 には手を入れない
- シミュレーションは固定刻み 1/240 秒の決定論計算にする。放物線は始点・終点・時間から初速を逆算し（`ballistic`）、ピンやバンパーは速度の変化の向きに置く。乱数はシミュレーションに使わない（火花などの見た目にだけ使う）
- シミュレーション部分を `// ===== SIM-BEGIN =====` と `// ===== SIM-END =====` で囲み、DOM に触れない書き方を守る。`scripts/chain-sim.mjs` がこの部分だけを Node で早送りし、`scripts/chain-sim.test.mjs` が「全段に到達して完走する」「2 回走らせて結果が一致する」を確かめる
- トップの画面には新ページへの導線を足さない（ボタン以外の UI を出さない方針のため）。README のリンクから辿る
- 段番号のランプをクリックすると、その段の 1.2 秒前まで計算だけを早送りしてから再生する。決定論なので、途中から始めても通しで見たときと同じ動きになる

## 捨てた案

- トップを置き換える: 既存の装置は「眺め続けるスクリーンセーバー」として独立した価値があり、ADR 0001〜0005 の前提もそのまま生きているため
- TypeScript のモジュールに分けて `src/` に統合する: 作業量が大きく、`src/lib/**` のカバレッジ方針（ADR 0003）とも噛み合わない。シミュレーションを HTML 内の囲みで分離し、Node で抜き出して検査する形で同じ目的（壊れたら CI で落ちる）を果たせる
- Matter.js で連鎖を組む: 衝突の結果が毎回変わり、最後まで届かないことがあるため

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 段の数と並び、各仕掛けの座標や所要時間、見た目と音、カメラの寄り方、`JUMP_LEAD`（途中再生で何秒前から始めるか）
- **壊すと危ない**:
  - SIM の囲みの中で DOM・`performance.now()`・`Math.random()` を使うこと。Node の早送りテストが動かなくなるか、毎回の結果が変わる
  - `setStage(k, ...)` の k と `STAGES` / `TAGS` の並びのずれ。ランプと途中再生の位置が別の段を指す
  - 装置を動かしたのに `CULL`（画面外を描かない範囲）を測り直さないこと。拡大時に装置が欠けて見える
