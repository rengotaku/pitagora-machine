# アーキテクチャ

ブラウザで動き続けるピタゴラ装置（ルーブ・ゴールドバーグ・マシン）。ページを開くとボールが投入され、坂・シーソー・発射装置・エレベーターなどの仕掛けを通って一周し、それが止まらずに繰り返される。

バックエンドは無い。Vite + TypeScript でビルドした静的ファイルだけで動く。

## 全体像

```
index.html
  └ src/main.ts                起動。canvas と設定パネルを組み立てる
      ├ src/machine/simulation.ts   ループの中心。ここが装置の配線を持つ
      │   ├ src/machine/world.ts        Matter.js の Engine と外周
      │   ├ src/machine/ball.ts         ボール生成
      │   └ src/machine/parts/*.ts      仕掛け（13 種類）
      ├ src/render/renderer.ts      Canvas 2D への自前描画
      ├ src/panel/settings-panel.ts 設定パネル（通常時は非表示）
      └ src/lib/*.ts                分岐を持つ純粋ロジック（テスト対象）
```

## どこを触れば何が変わるか

| やりたいこと | 触る場所 |
|---|---|
| 仕掛けの配置・接続を変える | `src/machine/simulation.ts`（座標と角度はここに集約） |
| 仕掛けの挙動そのものを変える | `src/machine/parts/<name>.ts` |
| 新しい仕掛けを足す | `src/machine/parts/` に追加し、`simulation.ts` で配置・配線・統計に追加。`src/types.d.ts` の `GimmickStats` にも項目を足す |
| 見た目を変える | `src/render/renderer.ts` と `src/config.ts`（色トークン） |
| ボールの個体差を変える | `src/lib/ball-variation.ts` |
| 詰まりの検知・回収の条件を変える | `src/lib/stall.ts`（停滞検知）、`src/lib/nudge.ts`（押し出し） |
| 投入のペースを変える | `src/lib/spawn-policy.ts` と `simulation.ts` の設定値 |
| 設定パネルの項目を変える | `src/panel/settings-panel.ts` と `src/lib/panel-settings.ts`（値の範囲） |

## 座標系

装置は **論理ワールド 1600 x 900**（左上原点・y 下向き）で組み立てる。表示時にアスペクト比を保ったままウィンドウへ収める（`src/lib/viewport.ts` の `fitWorldToCanvas`）。

ウィンドウサイズによって装置のレイアウトが変わらないので、「どの画面でも詰まらない」ことを検証できる。カメラは固定で、スクロールは発生しない。

## ループの構造

```
requestAnimationFrame
  └ tick(now)
      ├ timestep.update(frameDelta)      → steps と effectiveMs を得る
      ├ runFixedSteps(steps, ...)        → 物理と「位置に依存する装置更新」を同じ刻みで交互に実行
      │     ├ Matter.Engine.update(fixedDeltaMs)
      │     ├ launcher.update(fixedDeltaMs)   センサー通過の検知
      │     └ elevator.update(fixedDeltaMs)   キャリアの駆動と受け渡し
      ├ 通過カウント / フェイルセーフ / nudge / 停滞検知     ← フレーム 1 回
      ├ 投入判断（spawn-policy）                            ← フレーム 1 回
      └ renderWorld()
```

**時間の扱いに 2 つの約束がある。**

1. 物理は固定タイムステップで進める。1 フレームで進めるステップ数には上限があり、超えた分は捨てる。タブから復帰した瞬間に数百ステップを一気に回して固まるのを防ぐため
2. 装置側のロジックには、生の `frameDelta` ではなく**打ち切り後の実効経過時間（`effectiveMs`）**を渡す。物理がほぼ進んでいないのにエレベーターだけ瞬間移動したり、停滞検知が誤発火して全ボールを回収したりするのを防ぐため

**位置に依存する検知・駆動は各ステップ内で更新する。** フレーム 1 回にすると、低 FPS で steps が複数になったときにセンサー通過を取りこぼし、循環が止まる。一定時間の変位で判定するもの（停滞検知）や統計はフレーム 1 回でよい。

## ボールが止まらない仕組み

3 段構えになっている。手前ほど軽い介入で、後ろほど強い。

| 段 | しきい値 | 何をするか |
|---|---|---|
| 経路そのもの | — | 詰まらない勾配・間隔・着地条件にしてある。**ここが本体** |
| nudge | 約 1.2 秒 | 停滞しかけたボールを軽く押す。数回で諦める |
| 停滞検知 → 回収 | 約 4.5 秒 | そのボールだけ取り除いて投入口へ戻す。装置と他のボールは動き続ける |
| 画面外のフェイルセーフ | 即時 | ワールド外へ出たボールを回収して再投入する |

**回収は異常時の保険であって通常経路ではない。** 回収頻度が上がったら、それは経路のどこかが詰まっている合図なので、nudge やしきい値ではなく経路を直す。

停滞の判定は速度ではなく**位置の変位**で行う。速度基準だと、仕掛けの隙間で微振動しているボール（速度は 0 でないが前に進まない）を取りこぼす。

エレベーターで運搬待ちのボールは「動いていない」が詰まってはいないため、nudge と停滞検知の対象から外す（`elevator.isHolding()`）。

## 装置の経路

```
投入口 → 坂1 → 分岐ゲート → 振り子 → ドミノ → シーソー
      → 発射装置 → 坂2 → 回転ホイール → バウンド床 → 下部振り子 → エレベーター → 投入口へ戻る
```

仕掛けは 13 種類。`window.__pitagora.gimmicks` に各仕掛けの通過回数が出るので、「置いてあるだけで一度も作動しない仕掛け」を数値で検出できる。

## 統計（`window.__pitagora`）

装置が正しく回っているかを機械的に判定するために公開している。目視だけに頼らない。

| フィールド | 意味 |
|---|---|
| `activeBalls` / `minActiveBalls` | 現在のボール数 / 起動以降の最小値。最小値が 0 になったら装置が止まったということ |
| `fps` | 直近の平均 |
| `elapsedMs` | 起動からの経過 |
| `recoveredBalls` | 停滞検知で回収した累計。**増え方が装置の健康状態を表す** |
| `outOfBoundsBalls` | 装置外へ出て回収した累計 |
| `gimmicks` | 仕掛けごとの通過回数 |

通過回数は**センサーへ入った瞬間に 1 回数え、出たら記録を消す**。出たときに消さないと「通ったことのあるボールの数」になってしまい、周回数を表さない。

## テストの方針

カバレッジ対象は **`src/lib/**` のみ**（しきい値 80%）。

装置の組み立て（`src/machine`）と描画（`src/render`）は Matter.js と Canvas の実挙動でしか壊れ方が出ず、単体テストでは検知できない。実際、「矩形パーツが全て消える」「ホイールの羽根が重なって 1 本になる」といった不具合は、いずれも**実ブラウザのスクリーンショットで初めて見つかった**。

これらは長時間稼働の実測とスクリーンショットで担保する。手順は `docs/verification.md` にある。

## 検証

```bash
make ci      # lint / format / 型 / カバレッジ / build（CI と同じゲート）
make run     # 開発サーバ
```

長時間の安定性は `scripts/verify-stability.mjs` で計測する。CDP でページを開き、一定間隔で `window.__pitagora` を回収しながらスクリーンショットと JS 例外・`console.error` を記録する。判定基準は `docs/verification.md` を参照。
